05 · Architecture

Every frame passes through eight stages

01

Ingestion

ESP32-CAM or webcam posts raw JPEG over HTTP at 5 FPS.

routes/camera.py

02

Preprocessing

BGR to LAB, CLAHE on the L channel, then back to BGR.

preprocessor.py

03

Detection

YOLOv8n at 640×640 finds people, PPE and machinery.

inference.py

04

Tracking

BoT-SORT with Re-ID keeps each worker's track ID.

botsort_reid.yaml

05

Association

Containment assigns each PPE box to its wearer.

inference.py

06

Safety engine

10 s window: confirm at 70%, clear at 30%.

safety_engine.py

07

Persistence

Evidence JPEG saved; incident row written to SQLite.

event_manager.py

08

Live dashboard

WebSocket pushes alerts and worker status instantly.

websocket_hub.py

SITEGUARD

05

Read the stages left to right, top row then bottom row. A frame arrives over HTTP from the ESP32-CAM. It is contrast-enhanced with CLAHE, run through YOLOv8n, and the people in it are tracked with BoT-SORT so each worker keeps the same ID across frames. PPE boxes are then assigned to the worker they sit inside. The highlighted stage, the safety engine, is where we decide whether a violation is real; it is the heart of the system and gets its own slide. Confirmed incidents are saved with photo evidence and pushed to the dashboard over WebSocket. Each card names the file that implements it, so the code structure mirrors the pipeline.

Four gaps define the next phase

3D proximity zones

Camera homography turns pixels into ground distance, so worker-to-machine gaps are measured in metres.

TinyML on the node

A tiny person-presence model on the ESP32 sends frames only when someone is in view.

Pose estimation

YOLOv8-pose keypoints to detect slips, falls from height and unsafe postures.

Two-way IoT actuation

Server sends alarm commands back in the frame response (or MQTT) to sound a buzzer on site.

SITEGUARD

17

We are honest about what is not done. One: proximity to machinery is only 2D today; a calibrated homography would give real ground distances. Two: the ESP32 streams every frame; a tiny on-device model could wake the stream only when a person is present, saving bandwidth and power. Three: bounding boxes cannot see a fall; pose keypoints can. Four, highlighted because it is the quickest win: alerts currently reach only the dashboard. The ESP32 already receives an HTTP response for every frame, so the server can put an alarm command in that response and the node can drive a buzzer and LED with no new infrastructure; MQTT is the production-scale alternative.
